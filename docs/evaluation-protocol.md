# 실제 서비스가 시간을 줄이는가

## 비교

- **manual:** AI 없이 기존 서식·사진 편집 도구로 이미지와 게시글을 직접 완성한다.
- **service:** 실제 앱에서 스타일을 설정·저장하고 문구·이미지를 생성한 뒤 검수·수정·완성한다. 생성 기능은 실제 API를 사용한다.
- 같은 상품 사진·확인 정보·가게 참고자료·완성 조건을 제공한다. 결과를 같은 픽셀로 복제하는 과제가 아니라 같은 요구사항의 홍보물을 만드는 과제다.
- 서비스 버전은 실제 Git 커밋으로 기록한다. 과거의 시험용 `service-v1` 함수를 다시 만들지 않는다.

## 첫 과제

실상품 하나의 일반 홍보 피드를 이미지·본문·해시태그까지 완성한다.
라인업·품절·인사이트는 실제 기능이 연결된 뒤 해당 작업을 따로 평가한다.
미구현 기능을 시험용 함수로 대신해서 서비스가 편리하다는 근거로 쓰지 않는다.

## 수행

1. 과제별 폴더에 원본 사진·상품 사실·가게 참고자료와 완료 조건을 고정한다. 입력 자료 위치·도구·평가자 관계를 기록한다.
2. 같은 사람이 manual과 service를 수행한다. 기존 수동 서식도 사용할 수 있다. 초기 스타일 설정과 설정 후 반복 제작은 서로 다른 과제로 기록한다.
3. 자료를 열고 입력을 시작할 때부터, 검수 후 이미지·본문이 사용 가능한 상태로 완성될 때까지 전체 시간을 잰다. 생성 대기·수정·재생성 시간을 포함한다.
4. 실제 게시 성공까지 측정하는 과제라면 양쪽 모두 같은 종료 조건을 적용한다. 단순 제작 과제와 섞지 않는다.
5. 최초 초안 뒤의 문구 수정·이미지 수정/재생성 회차를 기록한다. 키 입력 수가 아니라 저장한 수정본/후보 한 회를 센다.
6. 원본·참고자료와 최종 결과를 대조하고 만족도를 직접 평가한다. 수행 순서와 사용 경험을 기록하고 반복할 때 순서를 바꿔 학습 효과를 확인한다.

## 판정

- **사실:** 상품명·구성·가격·판매 기간 등 확인 사실이 맞고 근거 없는 사실을 추가하지 않았는가.
- **스타일:** 저장한 말투·색감·배경·구도가 가게 참고자료와 맞는가. 저장된 스타일을 다른 상품에도 적용해 유지 여부를 확인한다.
- **상품 보존:** 이미지의 상품 종류·개수·형태·색·토핑이 원본과 맞는가. 상품 보존이 적용되지 않는 과제만 na로 표시한다.
- **사용 가능:** 정한 조건을 충족해 실제 게시할 수 있는가. 미완성·실패 결과도 남긴다.
- **만족도:** 1 매우 불만족 / 2 불만족 / 3 보통 / 4 만족 / 5 매우 만족. 프로젝트의 초기 자기보고 척도이며 검증된 사업 성과 지표는 아니다.

수정 2회 이내와 스토리 약 5초·피드 약 15초는 초기 목표다. 수정 횟수로 사용을 차단하지 않으며 AI 호출에는 기존 비용 한도가 적용된다.
만족도·정확성·수정 부담을 하나의 점수로 합치지 않는다. 사람 판정 전에는 unreviewed로 남긴다.

## 기록과 해석

[CSV 기록표와 집계](../evaluations/README.md)에 실제 측정만 작성한다.
같은 과제·평가자의 양쪽 결과가 품질 조건을 충족할 때만 시간 절감률을 계산한다.
실패·미평가·느려진 결과를 삭제하지 않는다. 비교 가능한 건수와 전체 수행 건수를 함께 보고한다.

개선 전 기록을 덮어쓰지 않고 개선본은 새 CSV와 Git 버전으로 남긴다.
본인·동료의 결과는 내부 평가이며 실제 카페 사장님의 반복 사용·수요·매출 검증으로 확대하지 않는다.
API 응답 시간은 진단용 기록이며 사람의 전체 작업 시간을 대신하지 않는다.

기존 자동 검사는 개발 오류 확인용으로 유지한다.
[26일 기술 점검](../evaluations/reports/pilot-2026-10-26/README.md)은 실상품 이미지·전체 작업 비교가 아니므로 메인 실험에 합산하지 않는다.
