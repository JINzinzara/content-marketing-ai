# 실제 서비스가 제작 시간을 줄이고 피드 일관성을 유지하는가

## 비교

- **manual:** 준비된 원본 사진을 수정 없이 사용하고 문구·해시태그를 직접 작성해 저장한다. AI와 이미지 생성·편집 도구는 사용하지 않는다. 기존 문구 서식은 사용할 수 있다.
- **service:** 실제 앱에서 스타일을 설정·저장하고 문구·이미지를 생성한 뒤 검수·수정·완성한다. 생성 기능은 실제 API를 사용한다.
- 같은 상품 사진·확인 정보·가게 참고자료·완성 조건을 제공한다. 결과를 같은 픽셀로 복제하는 과제가 아니라 같은 요구사항의 홍보물을 만드는 과제다.
- 서비스 버전은 실제 Git 커밋으로 기록한다. 과거의 시험용 `service-v1` 함수를 다시 만들지 않는다.
- 핵심 가설은 저장한 스타일로 서로 다른 상품 사진을 재생성하면 피드 분위기를 유지하는 수고를 줄일 수 있다는 것이다. 수작업에 이미지 편집이나 배경 재현을 요구하지 않지만, 원본 사진으로 구성된 피드의 일관성도 동일하게 평가한다. 범용 AI 대비 차별성은 이 비교로 입증하지 않는다.

## 첫 과제

실상품 하나의 일반 홍보 피드를 이미지·본문·해시태그까지 완성한다.
반복 사용에는 같은 가게의 다른 상품 사진을 사용한다. 한 장만으로 피드 일관성을 판정하지 않고 첫 사용·반복 사용의 여러 결과를 기존 피드·가게 참고자료와 함께 확인한다.
라인업·품절은 실제 기능이 연결된 뒤 해당 작업을 따로 평가한다. 반응 분석은 제작 평가 이후 독립적으로 평가한다.
미구현 기능을 시험용 함수로 대신해서 서비스가 편리하다는 근거로 쓰지 않는다.

## 시간 범위

- **first_use · 첫 사용:** 로그인 완료 → 스타일 설정 시작 → 콘텐츠 제작 → 완성본 확정 성공. 스타일 설정·참고자료 확인·저장 시간을 포함한다.
- **repeat_use · 반복 사용:** 저장된 스타일로 새 콘텐츠 제작 시작 → 완성본 확정 성공. 기존 스타일을 유지하며 새 상품의 제작을 진행한다.
- 수작업의 첫 사용은 가게 참고자료를 확인하고 문구의 말투·서식을 정하기 시작할 때부터, 반복 사용은 기존 말투·서식으로 새 상품 제작을 시작할 때부터 잰다. 앱의 스타일 입력 화면을 수작업에 강요하지 않는다.
- 앱은 버튼 클릭이 아니라 완성본이 저장되어 확정 완료가 확인된 시점에 끝낸다. 수작업은 원본 사진과 최종 문구가 게시 준비된 상태로 저장되고 완성을 선언한 시점에 끝낸다. Instagram 게시 시간은 포함하지 않는다.

## 수행

1. 과제별 폴더에 원본 사진·상품 사실·가게 참고자료와 완료 조건을 고정한다. 입력 자료 위치·도구·평가자 관계를 기록한다.
2. 같은 사람이 manual과 service를 수행한다. 첫 사용과 반복 사용을 scenario로 구분하고 시작 상태·사용 도구를 notes에 남긴다.
3. 위 시간 범위로 전체 시간을 잰다. 생성 대기·검수·수정·재생성 시간도 포함한다. 수정 횟수 자체는 측정·점수화하지 않는다.
4. 원본·참고자료와 최종 결과를 대조하고 만족도를 직접 평가한다. 수행 순서와 사용 경험을 기록하고 반복할 때 순서를 바꿔 학습 효과를 확인한다.

## 판정

- **사실:** 상품명·구성·가격·판매 기간 등 확인 사실이 맞고 근거 없는 사실을 추가하지 않았는가.
- **피드 일관성(style_ok):** 양쪽 결과 사진을 같은 순서·배치로 나란히 보고 가게 참고자료의 분위기와 맞는지, 여러 상품의 색감·조명·배경 분위기가 이어지는지 판단한다. 수작업은 원본 그대로, 서비스는 저장 스타일로 재생성한 결과를 평가한다. 원본이 이미 일관적이거나 재생성 결과가 더 나빠진 사례도 남긴다. 판정 근거·함께 본 결과물 위치와 문구 말투의 적합성은 notes에 적는다. 나란히 놓고 판정하는 시간은 제작 시간에 넣지 않는다.
- **상품 보존:** 이미지의 상품 종류·개수·형태·색·토핑이 원본과 맞는가. 상품 보존이 적용되지 않는 과제만 na로 표시한다.
- **사용 가능:** 필수 이미지·문구가 완성되어 게시할 수 있는가. 피드 일관성과 별도로 판정하고 미완성·실패 결과도 남긴다.
- **만족도:** 1 매우 불만족 / 2 불만족 / 3 보통 / 4 만족 / 5 매우 만족. 프로젝트의 초기 자기보고 척도이며 검증된 사업 성과 지표는 아니다.

주 지표는 전체 시간과 완성도이며 피드 일관성·만족도를 별도로 기록한다. 수정 횟수는 평가 지표·기록표·집계에서 제외한다.
현재 이미지 요청 한도(최초 생성 포함 총 2회)와 비용 제한 코드는 변경하지 않는다. 한도 내에 완성하지 못한 결과도 실패 사유와 함께 남긴다.
초기 스토리 약 5초·피드 약 15초 목표를 전체 작업의 합격선으로 사용하지 않는다. 사람 판정 전에는 unreviewed로 남긴다.

## 기록과 해석

[CSV 기록표와 집계](../evaluations/README.md)에 실제 측정만 작성한다.
같은 과제·사용 시나리오·평가자의 양쪽 결과가 사실·상품 보존·사용 가능 조건을 충족할 때 시간 절감률을 계산한다. 피드 일관성이 낮거나 미평가라는 이유로 시간 비교에서 제외하지 않고 일관성 결과를 따로 표시한다. 미평가 일관성을 서비스 효과로 주장하지 않는다. 첫 사용과 반복 사용을 합쳐 평균내지 않는다.
시간과 일관성을 함께 해석한다. 서비스가 더 오래 걸리면 시간 절감이라고 주장하지 않는다. 일관성도 개선된 경우에만 일관성 유지에 든 추가 시간으로 보고한다. 같은 품질을 더 빨리 만들었다는 주장과도 구분한다.
같은 사진 묶음의 일관성 판정을 여러 행에 적더라도 독립된 평가 건수로 중복 합산하지 않는다.
실패·미평가·느려진 결과를 삭제하지 않는다. 비교 가능한 건수와 전체 수행 건수를 함께 보고한다.

개선 전 기록을 덮어쓰지 않고 개선본은 새 CSV와 Git 버전으로 남긴다.
본인·동료의 결과는 내부 평가이며 실제 카페 사장님의 반복 사용·수요·매출 검증으로 확대하지 않는다.
API 응답 시간은 진단용 기록이며 사람의 전체 작업 시간을 대신하지 않는다.

## 다음 단계: 반응 분석 독립 평가

제작 시간·완성도 비교를 먼저 진행한다. 이후 아래 세 항목을 각각 평가하며 제작 점수와 합산하지 않는다.

- **분석 정확성:** 일반 홍보 Feed만 같은 목적·게시 경과 시간으로 비교하는가. 라인업·Story 제외, 결측과 0 구분, 지표 계산을 확인한다.
- **타당성:** 브리핑의 관찰·수치가 근거와 일치하고, 추측을 사실·인과관계로 단정하지 않으며, 실행 가능한 다음 행동과 제한 이유를 설명하는가.
- **추천 반영 정확성:** 사용자가 선택한 추천만 다음 제작에 반영하고 상품 사실·가게 스타일을 유지하는가. 선택하지 않은 추천이 자동 반영되지 않는지도 확인한다.

준비된 관측 데이터로 동작을 검사할 수 있지만 실제 고객 반응·방문·매출 향상 효과로 해석하지 않는다. 기존 자동 검사는 개발 점검이며 이 세 항목의 평가 완료를 뜻하지 않는다.

기존 자동 검사는 개발 오류 확인용으로 유지한다.
[26일 기술 점검](../evaluations/reports/pilot-2026-10-26/README.md)은 실상품 이미지·전체 작업 비교가 아니므로 메인 실험에 합산하지 않는다.
