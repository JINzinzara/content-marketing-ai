# 함수명 동기화와 실행 오류 수정 — 2026-10-21

기준 커밋: `f8bb10a`. 기존 저장소를 새 가상환경에서 실행하면 `app.ai`를 찾지 못해 테스트 수집부터 실패했다.
기존 로컬 설치가 누락 모듈을 대신 불러오지 않도록 독립 환경에서 재현했다.

## 이름 동기화

- 로컬 `app/ai.py` → `app/text_ai.py`, `AI` → `TextAI`.
- 로컬 `validate_draft_facts()` → `validate_draft()`.
- 로컬 `Settings.redirect_uri` → `Settings.redirect_url`.
- 로컬 `original_photo()` → `original_image()`.
- 저장소의 `exchage_code()`는 오타이므로 `exchange_code()`로 수정했다.
- Python 속성명과 달리 외부 OAuth 필드는 계속 `redirect_uri`를 사용한다.
- 호출부·import·테스트까지 변경했다. 앱 모듈과 클래스 메서드 이름을 양쪽에서 비교했다.

## 오류가 발생했던 지점

### 앱 시작과 데이터 접근

- `main.py`가 없는 `.ai.AI`를 import했다. `.text_ai.TextAI`로 연결했다.
- `auth.py`에 라우트 의존성인 `owner()`가 누락되어 있었다. 로컬 사용자와 공개 모드 인증 검사를 복구했다.
- `db.py`의 `table_into`, `SELLECT`, `SELET` 오타를 수정했다. 스키마 재시작과 소유자·게시물 조회가 실패하던 원인이다.
- `image_ai.recover()`의 문자열을 SQL 바인딩 튜플로 전달하지 않아 앱 생성 중 오류가 났다.
- `.gitignore`의 `assets/`가 하위 글꼴까지 제외해 `/fonts` 정적 경로 생성이 실패했다. 제외 범위를 루트 `/assets/`로 좁히고 글꼴·라이선스를 포함했다.
- 업로드 크기 검사에서 HTTP 헤더를 `content_length`로 읽었다. 실제 이름인 `content-length`로 수정했다.

### 스타일과 화면

- 스타일 필드 `backgound`, 이력의 `cation`, `SELECT +`, ID·이미지 URL 혼동을 수정했다. HTTPS 사진 주소도 올바르게 인정한다.
- 스타일 조합의 `elif/else`가 고정 항목 분기 안에 들어가 비고정 항목이 누락됐다. 분기를 같은 수준으로 옮겼다.
- 정수 버전인 `PRESET_VERSION`을 선택지 사전처럼 조회했다. 표시 이름은 `PRESETS`에서 가져온다.
- `latest_profile(con.who)`, `uncertanties`, 폼의 `reference_ids`/`reference_id` 불일치를 수정했다.
- `SELECT COUNT(*)` 결과 행 자체를 bool로 변환해 미차감 게시물도 차감 완료로 표시했다. 실제 원장 존재 여부를 조회한다.
- 게시물 조회의 `SELCET`, 후보 선택의 `post_ids`, 동기화의 `len(str)`, 분석 화면의 `metirc_names`, `/purchase` 앞 슬래시 누락을 수정했다.
- 편집 규격 정규식 앞부분 누락을 수정해 잘못된 규격이 저장되거나 렌더링 오류를 만들지 못하게 했다.
- 화면 문구가 바뀌어도 무료 제작권 재지급 시험은 게시물·잔액을 확인하도록 했다.

### 텍스트와 이미지 생성

- 정의되지 않은 `check_allowance`, `facts.pop[...]`, `usage.get[...]` 호출을 수정했다.
- 출력 토큰이 0이면 원가 기록을 건너뛰던 조건을 수정했다.
- 이미지 한도 비교가 `attempts > -limit`여서 첫 요청부터 차단됐다. `attempts >= limit`으로 수정했다.
- 원본 경로 `original`/`originals`, `Bearer` 뒤 공백, `_finish_error` 호출, `type(v) in int`, 오류 상태 SQL의 불필요한 쉼표를 수정했다.

### Instagram 인증·조회·게시

- `cliend_id`, `redirect_url`, `client`, `expires_int`, `access_toekn`을 실제 OAuth 요청·응답 필드에 맞췄다.
- 콜백의 `savve_connection`, 갱신 SQL의 `token_issues_at`, 이력 저장의 `NSERT`, 처리 중 상태의 `UPTDATE ... publish_massege?`를 수정했다.
- HTTP 403을 토큰 만료로 먼저 처리하던 분기를 수정해 인증 실패 401과 권한 부족 403을 구분한다.

## 이전에 합의한 동작 반영

신규 게시물 로고 업로드·자동 삽입을 제거하고 기존 확정 자료의 재현은 보존했다.
수동 참고자료는 선택 사항으로 두고, 문구 생성에는 상품 사진·확정 스타일·확인된 기존 본문 예시를 함께 전달한다.
자료 속 명령을 실행하지 않는 규칙과 다른 가게 자료 접근 차단을 유지한다.
