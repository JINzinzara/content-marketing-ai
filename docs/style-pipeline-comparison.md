# 인스타 스타일 분석이 문구·이미지에 미치는 차이

2026-10-29 사용자 수정 요청을 반영한다. 새 할로윈 상품 사진은 스타일 추출 근거로 사용하지 않는다.

## 비교 흐름

1. 이전 확정 스타일에서 사용한 인스타 게시물 8개의 사진·캡션·순서·게시물 ID를 고정한다. 원본은 계정의 기존 게시물이다. 사진을 실험 폴더에 보관해 만료되는 CDN 주소를 다시 읽지 않는다.
2. 같은 자료와 같은 앱 지시·Style 스키마로 5.4와 mini가 각각 한 번 스타일을 분석한다. 이전 확정 5.4 분석도 별도로 보존하지만, 이번 비교에서는 두 후보 모두 같은 고정 자료로 새로 분석한다.
3. 각 분석을 수정 없이 다음 제작에 적용한다. 앱의 keep 스타일 합성 규칙을 메모리 DB에서 실행하며 실제 가게 프로필은 덮어쓰지 않는다.
4. 같은 스푸키쿠키 입력 5개(원본 1장·합성 변형 4장)로 문구·이미지를 생성한다. 두 경로 모두 문구 모델은 gpt-5.4-mini, 이미지 모델은 gpt-image-2다. 상품 사실·프롬프트 형식·과거 캡션·생성 설정은 공통이고, 추출한 스타일 내용만 다르다.

스타일 분석 2건 + 문구 10건 + 이미지 10건 = **유료 생성 22건**이다. 토큰 사전 계산 HTTP 요청은 별도다. 각 입력의 최초 시도만 사용하고, 실패·거절·불명도 남긴다. 생성 원본과 최종 1080×1350 미리보기를 모두 보관한다. 이미지 설정은 low·1024×1024, 텍스트 설정은 추론 none·출력 2048·표준 처리 등급으로 고정한다. 입력과 요청·분석 출력의 의존 관계를 해시로 보존한다.

이미지 생성의 무작위성이 있으므로 결과 차이를 모두 스타일 분석 모델의 인과 효과로 단정하지 않는다. 모델별 스타일 분석은 이번 한 피드에서 1회다. 다른 카페·상품·실제 별도 촬영·반복 안정성까지 검증한 것은 아니다.

## 사람 평가

비교 화면에는 원래 인스타 사진·캡션과, 경로 A/B에서 만든 상품 이미지·문구를 나란히 보여준다. 경로의 모델명·비용은 가린다. 같은 A/B 표시는 스타일 분석부터 모든 후속 생성까지 유지된다. 요약 문장 자체의 문학성보다 **최종 결과가 기존 피드와 얼마나 이어지는지**를 본다.

- `reviews.csv`: 문구 10행·이미지 10행. 기존 상품 사실·기간·말투·형식·태그와 상품 보존·스타일·자연스러움·출력 규격 기준을 그대로 확인한다. T/H 코드 대신 한글 기준명을 열에 표시한다. 해당 영역만 채우고 다른 영역은 비워 둔다.
- `bundles.csv`: 문구 A/B·이미지 A/B, 총 4행. **기존 게시물 일치**와 **묶음 일관성**을 별도로 판정한다. 개별 품질 합격과 두 묶음 판정은 따로 집계한다.
- `preferences.csv`: 문구·이미지 각 한 행. A 우세/비슷함/B 우세 및 이유를 쓴다.

등급은 충족/부분 충족/미충족, 빈칸은 미평가다. 부분 충족은 합격이 아니며 개선 기록으로 남긴다. 충족은 이유 생략 가능, 문제가 있으면 결과당 한 번 구체적인 이유를 적는다. 모든 선호 판정에는 이유가 필요하다. 공통 평가자는 evaluator.txt의 본인이다. AI가 사람 판정을 대신 작성하지 않는다.

## 실행·집계·비용

```bash
cd /Users/limhyunjin/Desktop/content-marketing-ai
.venv/bin/python style_pipeline_compare.py prepare --references '<고정한 인스타 reference-set.json>' --out comparison/runs/instagram-style-pipeline-01
.venv/bin/python style_pipeline_compare.py run comparison/runs/instagram-style-pipeline-01 --execute
open comparison/runs/instagram-style-pipeline-01/review.html
```

기본 run은 남은 계획만 보여주며 --execute만 유료다. 실제 게시·스타일 확정·제작권 차감은 하지 않고 기존 누적 예산 원장을 공유한다. 예산을 자동으로 올리지 않는다. 스타일 단계가 실패·불명이면 그 출력을 다른 스타일로 대체하거나 같은 슬롯을 다시 호출하지 않는다. 두 분석이 완성된 뒤에만 후속 20개 요청을 별도의 고정 명세로 만든다.

```bash
.venv/bin/python style_pipeline_compare.py report comparison/runs/instagram-style-pipeline-01
```

단계별 비용·API 시간과 경로별 비용을 나눠 표시한다. 경로 비용에는 스타일 분석 1건과 후속 생성 10건을 모두 포함한다. 게시물 쌍의 합격은 실제 비교 화면에서 검토한 같은 입력의 문구·이미지가 모두 합격했을 때만 센다. 경로의 합격 게시물당 비용은 해당 경로 전체 비용을 합격 쌍 수로 나누며, 미전송·미평가·비용 불명이 남으면 계산하지 않는다. 묶음의 기존 피드 일치·일관성은 별도 표시한다.

API 시간을 실제 브라우저의 제작 버튼→준비 시간으로 부르지 않는다. 이미지 비용은 캐시 할인 미적용 상한 추정, 텍스트는 표준 단가의 사용량 추정이다. 청구 확인 전 확정 비용으로 부르지 않는다. 실패에 청구된 비용도 남긴다.

비용 불명·예약 초과는 제공사 청구 기록을 확인한 뒤 해당 단계로 정산한다. styles는 분석, content는 후속 제작 단계다. 실제 확인 금액·근거를 쓰며 임의로 0을 채우지 않는다.

```bash
.venv/bin/python style_pipeline_compare.py settle comparison/runs/instagram-style-pipeline-01 --stage styles --sample '<실제 ID>' --cost-usd '<확인 금액>' --note '청구 확인 근거'
```

정산은 같은 슬롯을 재생성하지 않는다. 이전에 잘못 설계한 상품 사진 기반 스타일 실험의 비용과 기록도 삭제하거나 이번 결과에 합쳐 숨기지 않는다.
