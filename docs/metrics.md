# 서비스 기대값 지표

## 지표 정의

사장님에게 필요한 것은 생성 요청 1회가 아니라 **바로 쓸 수 있는 홍보물 1건**이다. 그래서 모델과 흐름을 다음 기준으로 비교한다.

| 지표 | 계산 | 의미 |
|---|---|---|
| 합격률 | 합격 수 ÷ 시도 수 | 기준(T01~T09, H01~H04)을 모두 충족한 결과 비율 |
| 기대 시도 수 | 1 ÷ 합격률 | 쓸 수 있는 결과 1건을 얻기까지 평균 생성 횟수 |
| 합격 1건당 비용 | 전체 비용 ÷ 합격 수 | 실패한 시도의 비용까지 포함한 실제 원가 |
| 기대 대기 시간 | API 중앙값 × 기대 시도 수 | 쓸 수 있는 결과 1건까지 사장님이 기다리는 시간 |
| 제작 소요 시간 | 앱의 `production_timings` 실측 | 사용자 조작을 포함한 실제 흐름 시간 |

수치는 `python -m backend.kpi_report`로 보관된 실험 요약(`backend/comparison/runs/*/summary.csv`)과 앱 실측 DB에서 다시 계산한다. 새 API 호출은 하지 않는다.

## 시행착오와 결과

### 1. 이미지 모델: 단가보다 합격 1건당 비용

| 모델 | 합격 | 1회 비용(USD) | 합격 1건당 비용(USD) | 기대 시도 수 | 기대 대기(초) |
|---|---|---|---|---|---|
| gpt-image-1-mini | 3/5 | 0.007450 | 0.012417 | 1.67 | 18.3 |
| gpt-image-2 | 5/5 | 0.010842 | 0.010842 | 1.00 | 13.4 |

- **가설:** 더 싼 Image 1 mini가 원가를 줄인다.
- **결과:** 1회 단가는 Image 2가 45.5% 비싸지만, 불합격 재시도를 포함하면 합격 1건당 비용은 **12.7% 낮고** 기대 대기 시간은 **27% 짧다**.
- **실패 원인:** Image 1 mini의 불합격 2건은 모두 H04(최종 4:5 미리보기에서 쿠키 양 끝 잘림)였다. 사람 선호도 Image 2가 우세했다("A는 쿠키 자체가 AI로 생성된 티가 많이 남").
- **결정:** Image 2 채택.

### 2. 문구 모델: 품질이 같으면 비용·시간

| 모델 | 합격 | 1건 비용(USD) | API 중앙값(초) |
|---|---|---|---|
| gpt-5.4 | 5/5 | 0.008333 | 4.3 |
| gpt-5.4-mini | 5/5 | 0.002390 | 2.2 |

- 두 모델 모두 5/5였고, 블라인드 선호에서는 mini가 우세했다("문장이 이어지는 느낌이고 더 간결", 5.4는 같은 단어 3회 이상 반복).
- mini로 비용 **71% 절감**, 응답 시간 **50% 단축**.

### 3. 스타일 분석: 분석 모델이 후속 문구 품질을 바꾼다

| 분석 모델 | 분석 비용(USD) | 분석 시간(초) | 후속 문구 합격 | 분석+후속 10건 비용(USD) |
|---|---|---|---|---|
| gpt-5.4 | 0.035000 | 16.9 | 3/5 | 0.104589 |
| gpt-5.4-mini | 0.010185 | 5.8 | 5/5 | 0.078127 |

- 후속 생성 모델을 고정하고 분석 모델만 바꿨다. mini 경로가 분석 비용 **71%**, 시간 **65%** 낮았다.
- 5.4 경로의 불합격 2건은 해시태그 중복 노출(T09)이었다. 이 발견으로 앱에서 본문과 태그의 중복 노출을 정리하도록 수정했다(커밋 `beb143d`). 실험에서 찾은 결함이 제품 수정으로 이어진 사례다.

### 4. 상품 보존 방식: SlimSAM 누끼에서 자동 편집으로

- **가설:** 누끼로 상품을 오려 붙이면 상품이 더 잘 보존된다.
- **결과:** 경계·영역 지정 등 사장님의 조작이 늘었고, 결과는 잘라 붙인 것처럼 부자연스러웠다.
- **결정:** 누끼 단계를 없애고 원본 전체를 자동 편집하는 방식으로 통일했다. 같은 원본으로 비교한 결과 이미지는 보고서 2-5에 있다.

## 정량 평가: 이미지 지표

사람 체크리스트는 20개 결과 모두 상품 보존(H01)을 "충족"으로 판정했다. 합격/불합격만으로는 모델 간 차이가 보이지 않는다. 그래서 비슷한 과제의 선행 연구가 쓰는 연속 지표로 다시 쟀다. 계산은 `python -m backend.eval_metrics`이며 API 호출은 없다.

### 지표 선정 근거

| 평가 대상 | 지표 | 근거 |
|---|---|---|
| 상품 보존 (주 지표) | 상품 영역 DINO(ViT-S/16) 코사인 유사도 | [DreamBooth](https://arxiv.org/abs/2208.12242)가 주제 충실도 지표로 제안. 같은 종류 안의 개체 차이를 CLIP보다 잘 구분하며, 사람 선호와의 상관도 더 높다고 보고됨(DINO 0.32, CLIP-I 0.27). |
| 상품 보존 | 상품 영역 CLIP-I(ViT-B/32) | DreamBooth의 보조 지표. 상품 재배치 연구 [Malhi et al. 2025](https://arxiv.org/abs/2503.08729)는 배경 영향을 빼려고 상품 영역만 잘라 DINO·CLIP-I를 계산했다(segmented DINO/CLIP-I). 이 프로젝트도 같은 방식이다. |
| 상품 보존 | LPIPS, PSNR, SSIM | 지각 유사도(LPIPS)와 화소 지표. 생성 편집은 상품도 새로 그리므로 PSNR·SSIM은 낮은 것이 정상이고, 조건 간 비교용으로만 쓴다. |
| 가게 스타일 일치 | VGG-16 Gram 행렬 스타일 거리 | 스타일 전이 연구(Gatys et al.)의 스타일 표현. CLIP 전역 유사도는 내용(쿠키·음료)과 스타일이 섞여, 1차 계산에서 원본 사진이 결과보다 피드와 더 비슷하게 나오는 오류를 보였다. 스타일 전용 지표인 [CSD](https://arxiv.org/abs/2404.01292)가 더 최신 대안이지만 2.4GB 가중치가 필요해 이번에는 쓰지 않았다. |
| 쓸 수 있는 결과 비율 | 합격률(사람 체크리스트) | 광고 이미지 생성 연구 [Du et al., ECCV 2024](https://arxiv.org/abs/2408.00418)는 "사용 가능 비율(availability rate)"을 핵심 지표로 쓰고, 광고는 상품이 같아야 하므로 FID가 적합하지 않다고 지적했다. |

도입하지 않은 지표: FID·IS는 수천 장 표본이 필요하고 상품 동일성이 아닌 분포 사실성을 잰다. 정답 캡션이 없어 BLEU·ROUGE도 쓰지 않는다.

### 결과

| 조건 | n | 상품 DINO↑ | 상품 CLIP-I↑ | LPIPS↓ | PSNR(dB)↑ | SSIM↑ | 피드 스타일 거리↓ |
|---|---|---|---|---|---|---|---|
| gpt-image-1-mini | 5 | 0.753 | 0.827 | 0.539 | 10.38 | 0.333 | 0.727 |
| gpt-image-2 | 5 | **0.894** | **0.878** | **0.300** | **12.39** | **0.455** | **0.696** |
| 스타일 분석 gpt-5.4-mini 경로 | 5 | 0.879 | 0.869 | 0.344 | 11.55 | 0.406 | 0.692 |
| 스타일 분석 gpt-5.4 경로 | 5 | 0.869 | 0.874 | 0.351 | 11.00 | 0.392 | 0.698 |
| 입력 사진(기준선) | 5 | - | - | - | - | - | 1.463 |

- **상품 보존:** gpt-image-2가 모든 상품 지표에서 앞섰다. DINO는 Image 1 mini 5장 전부(0.71~0.79)를 Image 2 5장 전부(0.84~0.91)보다 낮게 평가했다. 사람 체크리스트가 놓친 "상품이 커지고 눈·형태가 바뀌는" 변형을 연속 지표가 잡아냈다.
- **가게 스타일:** 결과 이미지의 피드 스타일 거리는 0.69~0.73으로, 입력 사진(1.463)보다 약 52% 가까워졌다. 어두운 할로윈 원본이 가게의 밝은 우드톤 피드 쪽으로 옮겨졌다는 수치 근거다.
- **스타일 분석 모델:** mini 경로와 5.4 경로의 이미지 지표 차이는 작다. 분석 모델의 차이는 이미지가 아니라 문구에서 드러났다(후속 문구 합격 5/5 대 3/5).

상품 영역 박스는 25장에 수동으로 지정했다(`backend/comparison/product_boxes.csv`). 박스 위치에 따라 값이 조금 달라질 수 있다.

## 현재 기대값

- **홍보물 1건 원가:** 문구 $0.0024 + 이미지 $0.0108 ≈ **$0.013**. 무료 완성본 5건의 원가는 약 $0.066이다.
- **앱 실측 1건:** 제작 시작부터 첫 AI 후보까지 83.1초, 이미지 생성 버튼부터 후보 준비까지 15.1초, 수정 요청부터 미리보기까지 0.7초.

## 한계

비교 실험은 한 가게·한 상품(원본 1장과 합성 4장)·평가자 1명 기준이다. 앱 실측은 1건뿐이다. 이 수치를 다른 카페나 상품, 매출, 시간 절감 효과로 일반화하지 않는다.

## 다음 측정: 반복 사용 실측

비교 실험이 모델 선택의 근거라면, 이 측정은 사장님이 실제로 앱을 쓸 때 걸리는 시간을 확인한다.

**조건**

- 저장된 가게 스타일을 사용한다. 스타일 설정 시간은 포함하지 않는다.
- 이전 실험에 쓰지 않은, 서로 다른 상품 사진 5장을 사용한다.
- 확정 모델(문구 gpt-5.4-mini, 이미지 gpt-image-2)만 사용한다. 예상 비용은 약 $0.07이다.
- 한 사람이 같은 순서로 진행한다. 측정 중 코드나 프롬프트를 바꾸지 않는다.

**절차 (사진 1장마다)**

1. 새 제작 화면에서 사진과 상품 정보를 입력하고 제작을 시작한다.
2. 이미지 생성을 실행해 첫 AI 후보가 나올 때까지 진행한다.
3. 필요하면 수정하고 확정한다.
4. 제작 화면의 품질 기록에 수정 회차와 사실·상품·스타일 판정을 저장한다.

앱이 다음 시간을 자동으로 기록한다.

| 구간 | 의미 |
|---|---|
| `initial_preview` | 제작 시작부터 문구와 원본 미리보기 표시까지 |
| `image_candidate` | 이미지 생성 버튼부터 후보 표시까지 |
| `creation_to_ai_candidate` | 제작 시작부터 첫 AI 후보까지(사용자 조작 포함) |
| `edit_preview` | 수정 요청부터 미리보기 갱신까지 |

**집계**

```bash
python -m backend.kpi_report . data/instagram-test/app.sqlite3
```

구간별 표본 수와 중앙값, 앱 품질 판정의 합격 수, 수정 회차 중앙값이 출력된다. `creation_to_ai_candidate`에서 `image_candidate`를 뺀 시간은 대부분 사용자 입력과 조작 시간이다(문구 미리보기 준비 시간 포함). 가장 긴 구간을 병목으로 보고, 반나절 안에 고칠 수 있으면 개선한 뒤 같은 조건으로 다시 측정한다.
