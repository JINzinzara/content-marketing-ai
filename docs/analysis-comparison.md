# 스타일 분석·추천 모델 비교

**설계 수정 — 2026-10-29:** 아래 스타일 사례는 새 상품 사진을 분석했으므로 기존 인스타 피드 기반의 가게 스타일 모델 선정 근거로 사용하지 않는다. 비용·원본·실행 기록은 보존한다. 실제 사용 흐름의 스타일 비교는 [인스타 스타일→문구·이미지 비교](style-pipeline-comparison.md)로 진행한다. 추천 합성 지표 사례는 별도 탐색 범위로 유지한다.

2026-10-29. `gpt-5.4-mini`와 `gpt-5.4`에 같은 입력을 주고 비교한다. 모델을 앱에 자동 적용하지 않는다.

## 범위

- 스타일 분석: 원본 1장과 합성 변형 4장, 사진별 한 번씩 모델당 5개 결과. 예시 캡션은 제공된 상품 사실로 구성한 합성 문구다. 실제 Instagram 피드의 대표 표본이 아니다.
- 추천: 실제 반응 관측이 없어 합성 지표 5개 상황을 사용한다. 앱의 `analytics.analyze`로 비교 가능한 자료를 만든 뒤 실제 추천 요청과 같은 필드만 보낸다. 원시 저장 건수·도달 수는 앱에서도 모델에게 보내지 않으므로 모델의 원시 지표 계산 능력을 검증했다고 주장하지 않는다.
- 두 기능×두 모델×다섯 입력 = 생성 20건. 입력 토큰 사전 계산 요청은 별도로 20회 발생할 수 있다.
- 앱과 같은 지시·이미지 detail=low·구조화 응답 스키마를 사용한다. 출력 한도 2048, 추론 none, 표준 처리 등급을 공통으로 고정한다. 별도 프롬프트 튜닝이나 자동 재시도는 하지 않는다.
- 다른 입력의 단회 결과다. 실제 고객 반응·매출·실제 촬영 전반·동일 입력의 반복 안정성을 입증하지 않는다. 표본 수 5는 이전 실험과 맞춘 초기 운영 선택이며 통계적 최적 표본 수가 아니다.

## 사람 평가

`review.html`에서 입력과 A/B 결과를 나란히 본다. `reviews.csv`는 결과당 한 행, 총 20행이다. 네 가지 한글 열에 `충족` / `부분 충족` / `미충족`을 입력한다. 빈칸은 미평가이며 부분 충족은 불합격이다.

1. **자료 일치:** 스타일은 실제 사진·캡션의 색감, 조명, 배경, 구도, 글자, 말투를 정확히 기술하는가. 추천은 입력된 비율·0·결측·시각·목적별 비교 범위를 정확히 해석하는가.
2. **근거 연결:** 스타일은 실제 참고 ID와 관찰 항목을 연결하는가. 추천은 입력의 게시물·관측과 설명이 연결되는가. 제공하지 않은 참고 ID나 수치를 만들지 않는가.
3. **단정 억제:** 스타일은 모르는 글꼴·정확한 색온도·재료를 확정하지 않는가. 추천은 관찰을 원인, 최적 게시 시각, 매출 효과로 단정하지 않고 관찰·가설·한계를 구분하는가.
4. **활용 가능:** 스타일은 다음 제작에 쓸 수 있을 만큼 구체적이며 미확인 항목은 정직하게 남기는가. 추천은 근거에 맞는 실행 가능한 다음 시도를 제안하는가. 문장이 단순히 긴 것에 가산점을 주지 않는다.

하나라도 부분 충족·미충족이면 `reason`에 해당 문제를 자연어로 한 번 쓴다. 충족에는 이유를 생략할 수 있다. 평가자는 `evaluator.txt`의 `본인`을 공통으로 사용한다. `preferences.csv`는 스타일 분석·추천 각 한 행이며 `A 우세` / `비슷함` / `B 우세`와 이유를 적는다. 모델명·비용이 있는 집계표는 사람 평가 후 확인한다.

기존 문구·이미지 비교의 `bundles.csv`는 만들지 않는다. 이번 입력들은 조명이나 지표 상황이 달라 분석 내용도 달라져야 하므로, 같은 설명을 반복하는지를 합격 조건으로 삼지 않는다. 사람 판정을 AI가 대신 작성하지 않는다.

## 실행과 보관

```bash
cd /Users/limhyunjin/Desktop/content-marketing-ai
.venv/bin/python analysis_compare.py prepare --out comparison/runs/analysis-mini-01
.venv/bin/python analysis_compare.py run comparison/runs/analysis-mini-01
.venv/bin/python analysis_compare.py run comparison/runs/analysis-mini-01 --execute
open comparison/runs/analysis-mini-01/review.html
```

`prepare`·기본 `run`·`report`는 유료 호출이 없다. `run --execute`만 유료다. 입력·스키마·모델 설정·단가·코드 해시를 고정한다. 같은 슬롯을 자동 재호출하지 않고 실패·사용량 누락·중단도 남긴다. 기존 앱의 누적 예산 원장을 공유하며 예산을 자동으로 올리지 않는다. 사람의 스타일 프로필·추천·제작권을 변경하지 않는다.

판정 저장 후 집계:

```bash
.venv/bin/python analysis_compare.py report comparison/runs/analysis-mini-01
open comparison/runs/analysis-mini-01/summary.csv
```

결과·원시 응답·토큰 사전 계산·사용량·요청 ID·API 시간과 CLI 준비 시간은 실행 폴더에 남는다. 실제 브라우저 버튼부터 준비까지의 사용자 대기 시간은 측정하지 않는다. 합격 1건당 비용은 해당 기능·모델의 모든 시도 비용을 합격 수로 나누며, 미전송·미평가·비용 불명이 남거나 합격이 0개면 계산하지 않는다. 단가 기반 비용은 청구액과 대조하기 전 추정치다.

응답·비용 불명은 제공사 기록을 확인한 뒤 같은 폴더로 정산한다. 실제 확인 금액과 근거를 사용하며 임의로 0을 채우지 않는다.

```bash
.venv/bin/python analysis_compare.py settle comparison/runs/analysis-mini-01 --sample '<실제 ID>' --cost-usd '<확인 금액>' --note '청구 확인 근거'
```

정산은 모델을 재호출하지 않는다. 기존 원장의 다른 초과 요청은 `model_compare.py budget`·`settle-call`로 확인한다. 사진·요청·사람 판정은 기존 `.gitignore`의 `comparison/runs/` 제외 규칙을 따른다.
